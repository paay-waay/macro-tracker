# 宏量 · 极简记录 3.0.0

可以直接部署的静态 PWA，无需安装依赖、构建、API Key 或服务器。

## 上传 GitHub Pages

1. 更新前，在旧版设置中导出 CSV，并保存一份旧站点代码。
2. 将本文件夹内的全部文件上传到现有 GitHub Pages 的发布目录，覆盖同名文件。`index.html` 应放在原来的位置；不要额外套一层 `macro-tracker` 文件夹导致网址变化。
3. 保持原 GitHub Pages 发布设置。如果本来从 `/docs` 发布，就把内容放入 `/docs`；如果从仓库根目录发布，就放入根目录。使用自定义域名时保留仓库原有的 `CNAME` 文件。
4. 等待部署完成，用原来记账的设备和浏览器打开原网址。第一次联网刷新后，新版会读取并迁移本机旧数据；若仍显示旧版，关闭旧标签或 PWA 再重新打开并刷新，**不要清除网站数据**。
5. 核对历史记录、常吃和目标，立即在新版“设置 → 下载完整备份 JSON”保存完整备份。

应用可部署在仓库子路径，所有资源、图标和离线缓存均使用相对路径。`.nojekyll` 已包含。公开上传本文件夹即可；不要把个人 CSV、JSON 备份上传到仓库。

## 旧数据兼容方式

- 保留数据库名称 `macro-tracker-v13` 和版本 2，不删除、不改写旧 `records`、`drafts`、`favorites`、`dailyTargets` 及旧设置。
- 第一次打开时，在 `meta` 中以独立键保存原始快照和新版数据；初始化与原始快照在同一个事务中完成。新版后续记录只进入独立数据层。
- 兼容 IndexedDB 中的 2.3.7 数据及旧 `macro_tracker_records_v8` / `macro_tracker_favorites_v8` 本地存储。相同日期优先 IndexedDB 数据。
- 较新的旧草稿会恢复为当前记录。若时间戳不足以判断，以正式记录为准；“设置 → 查看旧版草稿”可预览并恢复其他草稿。
- 旧 C/F、日型、训练、饥饿、睡眠评分、设置和原始目标仍保留。主界面不再要求补填这些字段。
- 旧版“保存过”不等于“全天记全”：升级后的旧日期默认未确认，不自动用来计算完整日均值。
- 新版沿用最近已保存的可用目标作为固定目标，不继续每日自动修正。没有可用目标时请在设置中填写。历史日期优先使用其原目标快照；调整目标从今天生效。
- 新旧版本不双向同步。升级后用新版继续记账；重新部署旧版只能看到旧版原数据及原草稿，新版新增内容需保留新版 JSON 备份。
- 不包含、也不上传任何个人饮食数据。

### 自动迁移的条件

数据属于浏览器的网站来源（协议、域名、端口），并保存在当前浏览器配置中。原网址、原浏览器、原设备更新可直接读取旧库。换设备、浏览器或域名，应先导出，再导入备份。GitHub 仓库代码本身不保存浏览器里的饮食记录。

## 常用操作

- 首页主要看热量空间和蛋白缺口，点“记录一餐 / 食物”直接输入。名称可选，C/F 可选。
- 蛋白或热量不知道时允许留空。未知不是零；有未估热量时暂停显示可用余额，有未知蛋白时不判断蛋白缺口。
- 常吃右侧“＋”一键添加；点名称可改份量。半份按相同成分比例缩放，只少吃米饭时需编辑本次数值。
- “存为常吃”把已记录的条目变成可复用模板；常吃管理中可编辑、置顶或移出，历史快照不跟随改变。
- 称重配方录入整锅各原料的总营养及成品总克数 / 份数。没有食品数据库；首次数据需取自可信标签、已知数值或合理估算。以后只改食用量。
- 每条确认后的记录立即保存。填写中的普通食物编辑框会保留草稿；可从首页继续。配方与目标编辑需点击保存。
- “今天已记全”只表示主要摄入没有漏记，不是保存按钮。新增、修改或移除食物后需要重新确认。
- 回顾显示完整日均值、可判断日的蛋白达标次数和体重记录。缺失日不会当作零，体重不会触发自动调目标。
- 记录、更改、移除和导入完成后可撤销最后一次操作。刷新后短期撤销入口消失；导入前快照仍可从设置下载。

## 备份与导入

**完整备份 JSON**：包含新版记录、模板组件、目标历史、原始迁移快照、导入前快照和普通编辑草稿。用于换设备和完整留档。输入草稿可在导入时选择恢复。

**CSV**：兼容旧表头、旧收藏区、中文、引号和多行名称。可导入旧版 CSV；新版导出保留旧字段，并增加完整性和来源列。CSV 无法完整表达配方份量、目标历史和全部快照，应同时保留 JSON。新版 CSV 不承诺旧版程序能识别新增列。

**导入预览**：显示日期与常吃数量，默认跳过已有日期和同 ID 常吃。勾选替换后才覆盖冲突内容。目标历史可单独选择恢复。导入前会持久保存恢复快照；失败事务不会留下半份数据。

**恢复快照**：设置中可下载导入前快照或升级前原始数据，随后通过导入入口读取。合并恢复不会自动删除后来新增的日期。

**多页面保护**：若另一页面已保存更新，旧页面再次写入会被拒绝，避免覆盖新记录。刷新后继续；普通编辑草稿会保留。

## 离线与隐私

首次联网成功加载后可离线使用；安装到手机主屏幕时使用原网址。无账户、广告、分析追踪、外部字体或网络食品 API。浏览器可能在清理、卸载或存储压力下移除数据；请定期下载 JSON。请求持久存储仅是辅助，不替代备份。

## 文件

- `index.html`、`styles.css`、`app.js`：界面与交互。
- `core.js`：数据、营养合计、导入及迁移。
- `storage.js`：数据库事务、原始快照、并发写入保护。
- `sw.js`、`manifest.json`、图标：离线和主屏幕安装。
- `.nojekyll`：静态发布。
- `VALIDATION.md`：交付验证范围。
