# 3.1 设计取舍

用户已经从 AI 得到整餐宏量，App 的工作是保存四个数、复用相同记录、显示当天余额。这个流程无需再判断来源、精度、单位、份数或食材组成。

## 最短路径

新食物：点「记一餐」→ 同屏填写四项宏量 → 保存。名称可选，空白保留为未知，不自动当零。键盘回车可依次移动到下一项。

重复食物：点首页常吃 → 立即加入 → 可以撤销。修改数量时直接改本次四项数值，不引入份量模型。近期记录也可以直接复用，避免每次都先建立收藏。

## 每日与每周

热量使用横向进度条及「已用 / 目标 / 剩余」；蛋白质显示独立进度与缺口，C/F 显示累计值。没有设定 C/F 目标时，不制造没有依据的“达标圈”。横条共享清晰起点，比多层圆环更容易读出当前量和缺口，也给记录保留空间。此选择是针对本次任务的设计判断，尚未做用户对比实验。

记录逐行显示名称、kcal、P/C/F，点行即编辑。每日不展示迁移、数据库、来源或恢复说明。仍保留「今天记完了」，因为自动把所有已记日期视为完整，会让少记的热量污染周平均。

周回顾以 7 根柱表示摄入；有完整目标时用目标线对齐各日，目标有变化时柱高表示各自目标的比例，柱上显示实际 kcal。没有完整目标时使用 kcal 统一尺度。浅色代表部分记录，空日留空。完整日均值与蛋白达标次数紧接图表。体重和数据管理折叠。

## 视觉层次

内容卡片用稳定的浅色表面、圆角与细微阴影分组；玻璃材质用于导航、设置按钮和模态遮罩。没有在各卡片之间叠加透明玻璃。数值、状态、操作各自承担明确层级，减少解释文案。

依据：Apple 将 Liquid Glass 用于导航和控制层，建议避免玻璃叠玻璃；NN/g 的渐进披露支持把低频功能移到展开区域，识别优于回忆支持直接呈现常吃和最近记录。这些原则支持本次实现，但不等于已经证明该版本能提高用户长期 adherence。
